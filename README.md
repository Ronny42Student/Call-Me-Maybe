## Description

**Call Me Maybe** is a function calling engine that translates natural-language user queries (e.g., *"What is the sum of 2 and 3?"*) into structured, machine-executable function calls matching predefined schemas:

```json
{
  "prompt": "What is the sum of 2 and 3?",
  "name": "fn_add_numbers",
  "parameters": {
    "a": 2.0,
    "b": 3.0
  }
}

```

Small language models (such as `Qwen/Qwen3-0.6B`) struggle to reliably produce valid JSON using prompting alone. This project solves that problem by implementing **constrained decoding**: at every token generation step, logits generated by the LLM are masked so that tokens violating valid JSON syntax or the function schema are set to `-inf`, guaranteeing 100% valid structure and accurate function selection.

The core algorithm enforces constrained decoding by intercepting the model's output logits token-by-token.

### Pipeline Execution Steps

1. **System Prompt Construction (`build_full_prompt`):**
Combines the user request with schema definitions formatted in clean JSON.
2. **LLM Forward Pass & Masking [🤖 AI]:**
The model computes probabilities over the vocabulary through `get_logits_from_input_ids()`. Allowed characters are calculated via `get_allowed_chars()`, and invalid token logits are set to `-inf`.
3. **Function Resolution (`resolve_function_name`):**
Restricts early tokens to allowed function names (`cache.allowed_fn`). As soon as prefix matching yields a single function candidate, the algorithm auto-completes the function name instantly without requiring further LLM sampling steps.
4. **Context Rescoping (`inject_parameters_bridge` & `build_function_scoped_prompt`):**
Appends `,"parameters":{` to the output buffer and rebuilds a compact prompt containing *only* the single resolved function schema.
5. **Parameter Decoding & Masking [🤖 AI]:**
For each token, the LLM generates raw logits, and `compute_generation_mask()` parses the partial JSON state:
* **Expecting Key:** Restricts logits to tokens opening string parameters.
* **Expecting Value (Number):** Restricts logits to digits, signs, and decimals (`cache.p4_numbers_only`).
* **Expecting Value (String):** Permits valid string tokens without breaking JSON syntax.
* **Target Count Reached:** Prohibits commas and forces closure (`}}`).


6. **Validation and Coercion (`process_prompt`):**
Parses generated JSON, converts numbers to `float` as requested by schema, and validates data structures using Pydantic.

## Design Decisions

* **Deterministic Function Completion:** When only one candidate function name remains during decoding, `resolve_function_name` completes the string directly. This saves inference steps and prevents name generation drift.
* **Dynamic Context Rescoping:** After function resolution, the prompt is re-seeded with a scoped schema (`build_function_scoped_prompt`). This reduces prompt noise for `Qwen3-0.6B` and improves argument extraction accuracy.
* **Strict Parameter Count Tracking:** Once the generated parameter count matches `cache.func_params`, further field additions are blocked, forcing immediate closing braces (`}}`).
* **Data Validation & Coercion:** Pydantic models (`BaseModel`) enforce final schema compliance, and numeric parameters are explicitly coerced to `float` where required.

## Performance Analysis

* **Accuracy:** Reaches 90%+ function selection and parameter extraction accuracy across varied test suites.
* **Structural Reliability:** Achieves 100% syntactically valid JSON output due to logit-level masking (`-inf`).
* **Execution Speed:** Processes standard test suites in **~1m 35s** (well under the 5-minute constraint specified in Section V.5).
* **Resource Efficiency:** Operates using `Qwen/Qwen3-0.6B` without heavy dependencies such as PyTorch, Hugging Face `transformers`, or `outlines`.

---

## Challenges Faced

1. **Schema-Agnostic Masking:** Initial implementations relied on hardcoded field checks for specific test cases. This was refactored into a completely generic state-machine mask driven solely by schema parameter types (`number`, `string`).
2. **Small Model Parameter Extraction:** Small 0.6B models tend to produce literal string copies rather than structured expressions. Providing clear parameter descriptions within the prompt system resolved extraction accuracy without hardcoding heuristics.
3. **Token-to-String Mapping:** Mapping raw token IDs to subword strings (handling leading space characters like `Ġ`) required clean dictionary caching (`cache.clean_dict_items`) to calculate exact logit masks.

---

## Testing Strategy

* **Manual Tracing:** Hand-traced execution states across edge cases (zero-parameter functions, single candidate functions, multiple parameters).
* **Schema Variance:** Validated against diverse function schemas, including numbers, text transformations, and multi-argument API definitions.
* **Type Coercion Verification:** Verified that integer values (e.g. `2`) are safely converted to float numbers (`2.0`) to satisfy schema constraints.
* **Linting & Type Checking:** Enforced strict compliance using `flake8` and `mypy` static type checking (`make lint`).
